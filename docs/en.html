Research interests

I study high-performance computing at Université Paris-Saclay, with a focus on GPU kernel development, CUDA performance optimization and compiler frontends. My recent work explores NVIDIA Blackwell / Thor: Tensor Core computation, asynchronous data movement, shared-memory layouts, low-precision GEMM, PTX semantics and generated instructions.

I aim to turn observations from microarchitecture experiments into kernel implementations, using reference outputs, performance measurements and disassembly to explain where an optimization helps and where it does not.

Research & projects

Blackwell / Thor CUDA kernel optimization

CUDA · Tensor Core · TMA / TMEM · Low-precision GEMM

Implemented FP16 × FP16 → FP32 GEMM on Thor using raw CUDA and inline PTX, exploring TMA data movement, TCGen05/TMEM, warp specialization and persistent scheduling. Also implemented NVFP4 E2M1 data, E4M3 block scaling and a requantization epilogue.

In 10 archived tc5b trials at 1024³, all results passed the reference comparison, with average performance reaching 92.7% of the cuBLAS Tensor Core reference (cublasGemmEx). This result is specific to that problem size and historical reference implementation, not all sizes or end-to-end model performance.

PTX semantics, typed IR and PTX → SASS validation

PTX · LLVM / NVVM · ptxas · nvdisasm

Separated PTX parsing, type and instruction semantics checks, and typed LLVM/NVVM IR emission into distinct layers, preserving address spaces and instruction modifiers. Frontend output is validated separately from the collaborating backend.

Archived 206 minimal static PTX test cases for B200: 205 valid inputs and one specification-based negative case. Compared O0/O3 compilation results and disassembly from two tools, retaining environment information and SHA-256 hashes to analyze core opcodes, operand layout and instruction emission protocols.

Static lowering shows what the compiler generates; it does not, on its own, establish a kernel's numerical correctness. Hardware execution, numerical comparisons and performance measurements are recorded separately.

C++ training runtime and parallel computing

Oct 2025 – Apr 2026 · Team project · C++ / SIMD / MPI

Contributed to GEMM, Conv2D, data loading and parts of the MPI synchronization runtime. Implemented blocking/packing and SIMD micro-kernels, and used gprof to locate matrix-multiplication bottlenecks.

Switching to BLAS reduced the time for one MNIST epoch from 13.27 s to 1.74 s. This improvement came from the BLAS switch, not the custom SIMD kernels. My MPI work included parameter registration, gradient bucketing and synchronization statistics.

How I work

For any performance number, I first check the inputs, timing scope, reference implementation and hardware path. I then use minimal controlled experiments, profiling and disassembly to investigate the cause. I keep evidence for performance, static code generation and numerical correctness separate, and retain experimental conditions and failed approaches.
